# Phase 6 — User Journeys (desk-research draft v1, 2026-10-01)
Hypotheses for validation. Each journey: trigger → stages → pain points → opportunities → success signal → dependencies. Scope: the six Tier-1/1-ops personas most central to the pitch. Journeys use "COP32" assumptions (dates/venue unconfirmed).

## J1 — Non-accredited international visitor (P1): "Can I take part, and how do I get around?"
| Stage | Actions | Touchpoints | Pain points | Opportunities |
|---|---|---|---|---|
| Discover (Months before) | Searches for COP32 public participation | Web app, search, social links | Unclear if public can join; scams | "Can I attend?" explainer; verified-source badge; link to official pages |
| Plan | Chooses dates, hotel, visa | Guide, checklist, accommodation info | Scarce/expensive beds; visa uncertainty | Accommodation guide with official partners; e-visa steps; budget tips |
| Prepare | Install app, set language, save agenda | App/web, agenda, offline pack | Overload; connectivity abroad | Offline city & event pack; reminders |
| Arrive | Airport → city → venue | Transport guide, map | Taxi scams, traffic | Transport options, safe-taxi info, road closure alerts |
| Attend | Enter, find sessions, queues | Agenda, map, capacity/queue info | Crowding, changes | Change alerts, wait-time info (data-dependent), itineraries |
| After | Share, read outcomes | Archive, summaries | Content disappears | Outcomes digest; keep city guide for future trips |
Success signals: completed pre-trip checklist; agenda saves; fewer support questions. Dependencies: host public-access rules, venue/transport data.

## J2 — Local Addis resident (P2): "What is this and how can I be part of it?"
| Stage | Actions | Touchpoints | Pain points | Opportunities |
|---|---|---|---|---|
| Awareness | Hears about COP32 on TV/social | Amharic landing page, share cards | English-only content | Plain Amharic explainers, audio versions |
| Interest | Looks for local events, volunteering | Local events list, volunteer info | Unclear where/how | "Near me / today" feed; sign-up links |
| Participation | Attends public events | Map, schedule, reminders | Traffic and closures | Closure alerts, public-transport tips |
| Legacy | Follows outcomes and follow-up | Archive, Green Legacy progress | Information fades | Local impact stories; commitments tracker |
Success: Amharic usage share; event attendance clicks; shares. Dependencies: host event data, Amharic editorial capacity, content moderation.

## J3 — Journalist (P3): "I need verified, timely information"
| Stage | Actions | Touchpoints | Pain points | Opportunities |
|---|---|---|---|---|
| Prepare | Checks accreditation steps, press centre location | Media section | Scattered official info | One page linking official accreditation; checklist |
| Cover | Follows press-conference calendar, grabs releases | Alerts, calendar, documents | Last-minute changes; weak venue Wi-Fi | Time-zone aware calendar; downloadable press kit; offline docs |
| Verify | Cross-checks statements | Verified-source feed, official links | Misinformation | Source labels; EN/AM releases |
| Follow-up | Revisits documents, outcomes | Archive, search | Broken links | Stable URLs, versioned docs |
Success: press kit downloads; alert opt-ins; positive press mentions (supports D6 #3). Dependencies: press-office cooperation, official accreditation data.

## J4 — Remote follower (P4): "What happened today in my time zone?"
Stages: discover (search/social) → choose topics → daily digest → watch key session (live/recorded with captions) → share → read outcome summary. Pain: time zones, jargon, scattered streams. Opportunities: web-first quick view, digest email/push, captions, plain-language summaries, link to official stream. Success: weekly active followers by country; digest open rates. Dependencies: stream links/rights; editorial capacity for summaries.

## J5 — Side-event organiser / exhibitor (P5): "Get my event found and handle changes"
Stages: learn process (host rules) → submit details via organiser portal → approval → publish listing (EN/AM) → promote with QR/link → handle changes (room/time) → track interest → archive materials. Pain: competition among hundreds of events, last-minute changes, no feedback. Opportunities: self-service portal, change notices to followers, aggregate interest counts. Success: share of side events listed; update turnaround time. Dependencies: host's side-event system and data feed; moderation workflow.

## J6 — Volunteer (P6): "Answer any visitor's question in seconds"
Stages: onboarding (training in app) → shift info → help visitors (offline FAQ, maps) → escalate (report issue) → feedback. Pain: inconsistent info, no network. Opportunities: volunteer mode, offline FAQ in EN/AM, quick report button, announcements. Success: time-to-answer; escalation resolution. Dependencies: volunteer programme and ops owner; role-based access.

## Cross-journey observations
1. Most journeys depend on **host data** (public-access rules, venue, transport, side events) — early partnership is critical (gates G1/G2).
2. **Time-zone correctness**, **Amharic quality**, **offline guide**, **change alerts** appear in nearly all journeys -> foundation features.
3. Staff/admin journey (P7) is hidden but decisive: content freshness determines product trust (Phases 15–16).
4. Journeys J1–J4 can be piloted before COP32 with public content (unlike J5/J6 which need host systems) — supports the mid-2027 pilot plan.
